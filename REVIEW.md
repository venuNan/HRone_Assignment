# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|-------------------------|---------------|-----------------------------------------------|------------------|
| 1 |Health endpoint| The health endpoint returned a predefined JSON response without checking whether MongoDB was running or accessible.|The endpoint returned a healthy status even when MongoDB was down or unreachable. |Modified the health endpoint to check MongoDB connectivity and report the service status based on whether the database is accessible.
|2| Punch-In endpoint | The endpoint did not check whether an employee's late arrival fell within the 10-minute grace period defined by the business rules. | Identified the missing validation while reviewing business rules R1–R10. | Added conditional checks to determine whether the employee's arrival was within the 10-minute grace period. Late minutes are recorded only when the employee exceeds the grace period. |
|3| Punch-In endpoint | The endpoint did not verify whether the employee existed in the database before creating an attendance log. As a result, attendance records could be created for non-existent employees. | While implementing the Punch-In endpoint, compared its logic with the employee lookup process and noticed that the result of `find_one()` was not checked to confirm that the employee existed. | Added a validation check to verify that the employee exists before creating an attendance log. If the employee does not exist, the endpoint rejects the request instead of creating an invalid attendance record.|
|4| `list_employees` endpoint |The pagination logic calculated the skip value as `page * page_size`, causing the first page of employees to be skipped when requesting page 1.|Discovered the issue while testing the `list_employees` endpoint and noticed that the first page did not return the expected employees.|Corrected the skip calculation to `(page - 1) * page_size`, ensuring that page 1 starts with the first employee and subsequent pages return the correct records.|
|5|`list_employees` endpoint|The endpoint counted all documents in the employees collection instead of counting only employees belonging to the requested department.|Discovered the issue while testing the endpoint. For example, when the Sales department had only 2 employees, the endpoint returned a total count of 9 because it counted employees across all departments.|Added a department filter to the document-counting query so that the total reflects only employees belonging to the requested department.|
